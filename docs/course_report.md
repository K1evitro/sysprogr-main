# Отчёт по курсу разработки REST API на Spring Boot

## Введение

В данном отчёте описывается, какие знания и навыки были получены в процессе изучения разработки серверных приложений на Java с использованием Spring Boot и связанных технологий.В качестве итогового результата реализована система мониторинга городских автобусов и установленных на них датчиков, включающая аутентификацию, авторизацию, журналирование действий и сбор телеметрии.

## Что было изучено

### Структура проекта и инструменты

Была освоена типовая структура Maven‑проекта: разделение на `src/main/java`, `src/main/resources`, `src/test`, использование `pom.xml` для управления зависимостями и настройками сборки. Настроена среда разработки (VS Code / IntelliJ) для работы с Java и Spring Boot, включая запуск встроенного сервера и подключение к PostgreSQL.Дополнительно были изучены форматы обмена данными и конфигураций (JSON, YAML) в контексте веб‑API.

### Работа с базой данных и JPA

В ходе курса изучались основы проектирования реляционных баз данных и работа с ними через Spring Data JPA.В проекте спроектирована схема с сущностями пользователей, ролей, прав доступа, автобусов, датчиков, показаний датчиков и файлов с данными.Через аннотации `@Entity`, `@OneToMany`, `@ManyToMany` реализованы связи между таблицами, а репозитории на основе `JpaRepository` обеспечивают стандартные CRUD‑операции без ручного SQL.Также рассматривались транзакции и их роль в обеспечении атомарности операций (например, при сохранении показаний датчиков и связанных логов).

### Безопасность и управление доступом

Отдельный блок был посвящён Spring Security: настройке аутентификации и авторизации, работе с `UserDetailsService` и хэшированию паролей с помощью bcrypt.[web:74] В итоговом проекте реализована ролевая модель доступа на основе сущностей User, Role и Permission, где права хранятся в формате `OPERATION_RESOURCE` (например, `READ_BUS`, `WRITE_SENSOR`, `READ_REPORT`).На уровне контроллеров используются аннотации `@PreAuthorize("hasAuthority('...')")`, что позволяет точно ограничивать доступ к CRUD‑операциям и формированию отчётов.

### REST API, валидация и обработка файлов

Курс охватывал принципы построения REST API, использование HTTP‑методов (GET, POST, PUT, DELETE) и работу с параметрами запросов через `@PathVariable` и `@RequestParam`. В проекте реализованы эндпоинты для управления автобусами, датчиками, показаниями и отчётами по аномалиям, а также операции загрузки и скачивания файлов с данными датчиков. Обсуждались вопросы безопасности параметров, валидации входных данных, корректной обработки кодировки URL и MIME‑типов при работе с `multipart/form-data`.

### Документирование и наблюдаемость

Отдельное внимание уделялось документированию и поддержке проекта. В репозитории оформлена папка `docs/` с логической ER‑диаграммой в формате Mermaid, физической схемой БД в виде DDL‑скрипта и поясняющим описанием таблиц. Для REST API настроена автогенерируемая документация (Swagger/OpenAPI), что позволяет удобно тестировать эндпоинты и демонстрировать функциональность на защите.Логирование с использованием SLF4J и аннотации `@Slf4j` применяется в сервисах и контроллерах для отслеживания ошибок, аномалий и ключевых операций.

## Применение знаний в итоговом проекте

### Архитектура и функциональность

Результатом применения изученных концепций стала система мониторинга автобусов и датчиков, построенная по многослойной архитектуре: контроллеры, сервисы, репозитории и слой безопасности.Пользователи с ролью ADMIN имеют полный доступ к управлению автобусами, датчиками и отчётами, а остальные пользователи ограничены правами чтения и скачивания данных.Через REST API и веб‑интерфейс можно просматривать список автобусов, состояние датчиков, историю показаний, а также формировать отчёты по аномалиям за заданный период.

### Работа с данными и отчётностью

Система регулярно сохраняет показания датчиков в базу данных, помечая аномальные значения по заданным правилам.На основе этих данных реализован эндпоинт формирования отчёта, который агрегирует аномалии по автобусам и периоду времени и предоставляет информацию как через API, так и через веб‑интерфейс.Функции загрузки файлов позволяют импортировать накопленные данные с бортовых систем, а механизм прав доступа ограничивает операции только для авторизованных пользователей.

## Источники информации

При выполнении курса и разработке проекта использовались следующие источники:
- официальная документация Spring Boot, Spring Security и Spring Data JPA;
- руководства по Maven и стандартной структуре Java‑проектов;
- материалы преподавателя по архитектуре веб‑API, работе с БД и вопросам безопасности;
- статьи и примеры из открытых ресурсов о проектировании REST сервисов и организации многоуровневых приложений.

## Заключение

В ходе курса была пройдена полная цепочка создания backend‑приложения: от настройки окружения и структуры проекта до реализации защищённого REST API с удобной документацией и работающей схемой базы данных.Итоговый проект демонстрирует умение применять теоретические знания на практике: проектировать структуру данных, реализовывать бизнес‑логику, обеспечивать безопасность и оформлять документацию, пригодную для деплоя и дальнейшего развития.
